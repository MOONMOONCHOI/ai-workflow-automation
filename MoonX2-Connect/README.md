# MoonX2-Connect (MoonX2BlogManager)

네이버 블로그 이웃 관리·소통을 자동화하는 Windows 데스크톱 프로그램.
여러 사용자 PC에 배포해 라이선스로 관리하고, 새 버전은 사용자가 아무것도 하지 않아도 자동으로 설치된다.

| 항목 | 내용 |
|---|---|
| 형태 | Windows 데스크톱 앱 (설치 없이 압축 해제 후 실행) |
| 기간 | 2026-09-14 ~ 2026-09-21 (첫 커밋부터 v1.3.1까지 33커밋) |
| 규모 | C#·Python 약 21,000줄, 테스트 파일 24개·테스트 671개 |
| 역할 | 기획·설계·개발·배포·운영 전부 (1인) |
| 스택 | C# .NET 8 WinForms · WebView2 · Python 3.11 · Playwright · PyInstaller · SQLite · GitHub Actions · Google Apps Script · Gemini / OpenAI API |

---

## 1. 무엇을 하는 프로그램인가

블로그를 키우려면 매일 이웃 글을 읽고 공감·댓글을 남기고, 서로이웃 신청을 받고 정리해야 한다.
이 반복 작업을 **작업(Task) 단위로 설정해 순서대로 돌리는** 프로그램이다.

| 작업 종류 | 하는 일 |
|---|---|
| 이웃 소통 | 대상 글을 모아 방문 → 공감 → AI 댓글 → 서로이웃 신청 |
| 받은 신청 처리 | 받은 서로이웃 신청을 수락하고, 제외 대상은 거절. 그룹(500명 한도)을 자동으로 나눔 |
| 보낸 신청 정리 | 오래 응답 없는 서로이웃 신청을 취소 |
| 이웃 목록 정리 | 조건에 맞는 이웃 삭제 (화이트리스트·보호 그룹 제외) |
| 받은 댓글 답글 | 내 글 댓글에서 매크로를 거르고 소통형 댓글에만 AI 답글 초안 작성 |
| 쉬어가기 | 작업 사이 대기 |

이웃 소통 작업의 대상은 6가지 출처에서 모은다: 내 이웃 새글 · 이웃 그룹 새글 · 주제 디렉터리 · 블로그 검색 · 다른 블로거의 이웃 · 직접 지정한 아이디.

그 밖에 안부글(방명록) 남기기, 한글 입력 오류로 잘못 달린 한 글자 댓글 정리, 운영 대시보드(활동 통계)가 있다.

## 2. 구조

```
[사용자 PC]
 MoonX2BlogManager.exe  ─ C# WinForms 런처
   · 화면(대시보드·작업 편집·설정), 네이버 로그인(WebView2)
   · 라이선스 확인, 자동 업데이트, 작업 순서 실행
        │ 프로필·작업 설정·환경변수 전달
        ▼
 blog_bridge_automation.exe ─ Python + Playwright 엔진 (PyInstaller 단일 파일)
   · 런처가 저장한 로그인 세션으로 네이버 화면을 사람처럼 열고 조작
   · 작업 기록 SQLite, 계정 보호 계층, AI 댓글 생성

[서버 없이 운영]
 GitHub Actions ──► 공개 배포 저장소 Release (zip · version.json)
 Google Sheets + Apps Script ──► 라이선스 확인(verify) · 관리자 동작
```

- **런처와 엔진 분리**: UI는 C#으로 가볍게, 브라우저 자동화는 Playwright 생태계가 가장 성숙한 Python으로.
  사용자는 파이썬을 설치할 필요가 없다 — 엔진은 PyInstaller로 묶어 exe 옆에 둔다.
- **별도 서버 비용 0원**: 배포는 GitHub Release, 라이선스는 구글 시트 + Apps Script 웹 앱으로 해결했다.

## 3. 핵심 설계와 해결한 문제

### 3-1. 계정을 지키는 안전 계층
자동화 프로그램의 가장 큰 위험은 사용자 계정이 제재를 받는 것이다. 동작 속도보다 **멈춰야 할 때 확실히 멈추는 것**을 우선했다.

- **하루 누적 한도**: 공감·댓글·서이추를 프로필별·날짜별로 세어, 하루에 여러 번 실행해도 한도를 넘지 않는다.
- **비상 정지**: 캡차·이용 제한 문구·로그인 풀림·연속 실패를 감지하면 실행 전체를 멈춘다.
  감지 문구를 다 알 수 없으므로 모르는 문구로 막히는 경우는 연속 실패 감지가 받쳐 준다.
- **안전 잠금**: 제재 신호로 멈췄으면 정해진 시간 동안 다시 시작하지 못하게 한다.
- **재시도 규칙**: 페이지 이동·요소 대기처럼 결과가 같은 동작만 재시도한다.
  댓글 등록·신청·수락·삭제처럼 누르는 순간 반영되는 동작은 재시도하지 않는다 (중복 댓글 방지).
- **"눌렀다"가 아니라 "반영됐다"를 센다**: 수락·취소·삭제 뒤 목록을 다시 읽어 실제로 사라진 줄만 성공으로 센다.
  누르기 전에는 체크된 줄이 고른 줄과 정확히 같은지 확인하고, 다르면 멈춘다.
- **삭제는 기본 잠금**: 이웃 삭제는 설정에서 명시적으로 허용하기 전까지 미리보기만 한다.

### 3-2. 네이버 화면을 실측으로 다루기
추측한 셀렉터는 조용히 실패한다. 모든 동작을 **실제 화면 DOM과 네이버 원본 스크립트를 확인한 뒤** 구현했고,
그 근거를 코드 주석에 날짜와 함께 남겼다.

- 대상 글 수집은 버튼을 누르는 대신, 사람이 여는 것과 같은 목록 주소로 이동해 **화면이 스스로 받는 응답을 가로채** 읽는다.
  네이버로 가는 요청이 사람이 화면을 여는 것과 같아진다.
- 블로그 통계(방문자·이웃 수·최근 글)는 스킨마다 있다 없다 하는 위젯 대신 모바일 API 응답에서 읽어,
  "위젯이 없으면 필터가 사실상 꺼지던" 문제를 고쳤다.
- 이웃 삭제는 목록 주소를 바로 열면 확인 창이 뜨지 않는다는 것을 실측으로 찾아, 관리 페이지의 프레임 안에서 열도록 바꿨다.
- 셀렉터 점검 도구(`--probe`)를 따로 만들어, 네이버 화면이 바뀌었을 때 어떤 요소가 안 잡히는지 읽기 전용으로 바로 확인한다.

### 3-3. 비용을 아끼는 2단계 댓글 분류
받은 댓글에 답글을 달 때, "잘 보고 갑니다" 같은 매크로 댓글 백 개를 AI에 보내는 것은 토큰 낭비다.

1. **1차 (로컬, 무료)**: 짧으면서 정형문인 댓글만 매크로로 뺀다. 인사로 시작해도 뒤에 할 말이 붙어 길면 남긴다
   — 진짜 댓글을 매크로로 버리는 쪽이 더 손해이기 때문.
2. **2차 (AI, 유료)**: 남은 댓글만 모아 한 번에 분류하고 답글 초안을 만든다.
   분류는 답글 쓸 댓글 / 지인·단문 / 검토 필요(제휴·비밀댓글) / 매크로 4갈래.

비밀댓글 본문은 기본값으로 AI에 보내지 않는다. 답글은 자동으로 올리지 않고, 사람이 확인·수정한 뒤 등록한다.
여러 건을 올릴 때는 도배로 보이지 않게 30~50초씩 간격을 둔다.

AI 공급자는 Gemini와 GPT 중 고를 수 있고, 키를 최대 5개까지 넣어 한도 초과·키 오류 시 다음 키로 넘어간다.

### 3-4. 사용자 손이 전혀 안 가는 자동 업데이트
여러 PC에 배포하는 프로그램이라 "PC마다 사람이 설정하는 단계"가 있으면 쓸 수 없다고 봤다.

- 버전 태그를 푸시하면 GitHub Actions가 Windows에서 테스트 → 엔진 빌드 → 런처 빌드 → 공개 배포 저장소에 Release를 올린다.
- 프로그램은 켤 때와 3시간마다 새 버전을 확인해 백그라운드로 받고, 크기·SHA-256을 검증한다.
- 돌고 있는 작업이나 열린 창이 없으면 잠깐 알린 뒤 다시 시작하며 설치하고, 작업 중이면 닫을 때나 다음 실행 때 설치한다.
- 설치는 새 런처가 옛 프로세스 종료를 기다린 뒤 파일을 바꾸고, 실패하면 되돌린다. 같은 버전이 두 번 실패하면 자동 설치를 멈춘다.
- 사용자가 실수로 엔진 파일을 지워도 필요한 파일을 다시 받아 스스로 복구한다.
- 사용자 PC에는 토큰이 없다. 배포 토큰은 CI 비밀 값에만 있다.

### 3-5. 서버 없는 라이선스
- 구글 시트 한 줄 = 키 하나. 관리자는 시트에서 상태·만료일·등록 PC를 고치는 것으로 차단·연장·초기화를 한다.
- 키 하나에 PC 최대 4대. HWID는 기기 고유값의 SHA-256이고, 시트에는 앞부분만 저장한다.
- 실행할 때와 6시간마다 확인. 서버에 닿지 못해도 마지막 성공 뒤 24시간까지는 계속 쓸 수 있고,
  차단·만료 응답을 받은 PC는 그 여유가 지워진다.
- **복제 방지**: 서버가 확인 성공 시 서명한 증명(PC·키에 묶임, 약 하루 유효)을 주고, 엔진이 공개 키로 검증한다.
  런처를 거치지 않고 엔진만 실행하면 멈춘다.
- 매일 GitHub Actions가 라이선스 서버를 점검해, 응답이 없으면 메일로 알린다.
- 기간 변경·접속 기록은 시트의 기록 탭에 남고 30일이 지나면 자동 정리된다.

### 3-6. 작업 기록과 중복 방지
- 프로필마다 SQLite 파일 하나에 방문·공감·댓글·서이추·삭제를 시각·결과(성공/실패/조건 제외)와 함께 남긴다.
- 같은 글은 다시 작업하지 않는다. 페이지를 열지 못한 실패만 다음에 재시도하고,
  공감·댓글을 누른 뒤의 실패는 재시도하지 않는다 — 판정이 틀렸을 때 댓글이 두 번 달리는 것을 막기 위해.
- DB 파일이 깨지면 옆에 보관하고 새로 시작한다.

## 4. 품질 관리

- **테스트 671개**: 작업 설정 해석, 안전 계층, 수집기, 신청 수락·취소, 이웃 정리, 댓글 분류, 라이선스, 빌드·릴리스 스크립트까지.
- **C#·Python 동등성 테스트**: 런처(C#)와 엔진(Python)이 같은 규칙(HWID·결과 코드·문구·설정 형식)을 쓰는지 검사한다.
- **Apps Script 테스트**: node가 있으면 라이선스 서버(.gs)의 동작까지 로컬에서 검사한다.
- **빌드 파이프라인**: `build.py` 한 번으로 환경 점검 → 테스트 → 엔진 빌드(소스가 그대로면 건너뜀) → 엔진 자체 점검 → 런처 빌드 → 결과 확인.
- **드라이런**: 네이버에 접속하지 않고 작업 설정·하루 한도·작업 기록만 점검하는 모드.
- **배포 전 검사**: 비밀 값·민감 파일이 커밋에 섞이지 않도록 릴리스 도구가 막는다.

## 5. 사용자 경험

- 압축 풀고 `시작하기.bat` 한 번 → 바탕화면 바로가기 생성, 필요한 구성요소(WebView2) 자동 설치.
- 말투별 추천 작업 설정 3종(친근·차분·발랄)을 불러와 바로 쓴다. 차분한 말투에는 이모티콘을 넣지 않는다.
- 작업은 "갈래 × 대상 출처" 두 축으로 고르게 정리해, 종류가 늘어도 편집 화면이 복잡해지지 않게 했다.
- 예전 이름으로 설치했던 PC는 첫 실행 때 로그인·작업·기록을 새 데이터 폴더로 자동으로 옮긴다.
- 로그인 창에서 "로그인 상태 유지"를 빠뜨리면 엔진 쪽 로그인이 풀리는 문제를 실측으로 찾아,
  저장된 쿠키에 로그인 정보가 있는지 미리 확인하고 안내한다.

## 6. 돌아보며

- **자동화의 신뢰는 "멈춤"에서 나온다.** 기능을 늘리는 것보다, 모르는 상황에서 누르지 않고 멈추는 규칙을 먼저 세웠다.
- **실측이 추측을 이긴다.** 네이버 화면을 직접 확인하고 근거를 주석에 남긴 덕에, 화면이 바뀌어도 어디를 고칠지 바로 안다.
- **운영 비용과 사용자 수고를 0에 가깝게.** 서버 없이 GitHub와 구글 시트로 배포·라이선스를 해결하고, 사용자는 설치 후 아무것도 하지 않는다.
